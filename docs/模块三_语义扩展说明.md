## 0. 一句话

前沿打分从**纯几何 FBE** 升级为 **几何 + 语义**，语义来自
**离线常识知识库 + 在线对象记忆 + 本地确定性评分**，**不在线调用任何生成式模型**。
同时把观察点评分向量化了约 15 倍，并给出"双前沿判别"评测脚本供服务器实测。

所有新参数都有默认值 `None`，**不传时行为与改动前完全一致**：

```python
ranked = explorer.rank(snapshot, records, mapping)          # 老调用方式，照常工作
```

`rank()` 是纯函数式调用，每次调用都新建候选对象，不会把语义分残留到下一次。

## 2. 为什么不在线调用 VLM

| 方案 | 延迟 | 抖动 | 可复现性 |
|---|---|---|---|
| 每轮排序问一次 Qwen | 数百 ms ~ 秒 | 高（提示词/采样敏感） | 差 |
| **离线知识库 + 本地评分** | **微秒** | **无** | **完全可复现** |

更关键的一点：感知环节已经把物体类别、属性、视觉线索提取出来了。
再让 VLM 对同一批信息做一次常识推理，属于**重复付费**。
我们的做法是把常识固化成 JSON，运行时只查表 + 几次乘加。

## 3. 算法

### 3.1 物体关联度

$$
A(o,g)=\max\Big(\underbrace{\textstyle\sum_{r}P(r\mid o)\,P(r\mid g)}_{\text{房间路径}},\;
\underbrace{\mathrm{cooc}(o,g)}_{\text{共现路径}}\Big)\in[0,1]
$$

- **房间路径**解决"词义不近但空间共现强"：马桶与洗手池词义上不相似，
  但房间分布几乎重合，点积 0.60；马桶与床只有 0.03。
- **共现路径**解决"同房间内仍有强弱之分"：遥控器↔电视 0.95。
- 同类物体直接取 1。

实测值：

```
A(马桶, 洗手池) = 0.600     A(椅子, 餐桌) = 0.950     A(椅子, 椅子) = 1.000
A(马桶, 床)     = 0.033     A(遥控器, 电视) = 0.950   A(冰箱, 床)   = 0.034
```

### 3.2 语义收益

$$
S(F,g)=\max_{o\in\mathcal{O}_F}\Big[A(o,g)\cdot c_o\cdot e^{-d_{\mathrm{geo}}(o,F)/\sigma}\Big]
$$

| 符号 | 含义 | 落地方式 |
|---|---|---|
| $\mathcal{O}_F$ | 观察点 8 m 内的记忆物体 | `object_query(viewpoint_xy, radius)` 回调（集成层绑定到 M2） |
| $c_o$ | 观测可靠性 | M2 状态映射：CONFIRMED 1.0 / CANDIDATE 0.7 / 未定位 0.25 / REJECTED 0 |
| $d_{\mathrm{geo}}$ | 物体到观察点的测地距离 | 目前用欧氏距离近似（见 §7 风险） |
| $\sigma$ | 语义影响半径 | 默认 4 m |

三条设计要点：

1. **取最大值而非求和** —— 无关物体不该稀释强证据；求和会让"堆满杂物的房间"得分虚高。
2. **历史调制** —— 访问过但没找到目标的区域，语义分按 $(1-\lambda)^v$ 衰减（$\lambda=0.6$）。
   没有这一条，知识库会反复把机器人送回"理论上最该有椅子"的餐厅。
3. **未接线即退化为纯几何** —— 没有 provider 时 $S\equiv0$，排序与改动前逐位一致。

### 3.3 权重（**注意：已变更**）

| 项 | 旧权重 | 新权重 |
|---|---|---|
| 信息增益 $I$ | 0.35 | **0.25** |
| 新颖性 $N$ | 0.15 | **0.10** |
| **语义 $S$** | 0（未实现） | **0.30** |
| 路径成本 $D$ | 0.20 | **0.15** |
| 历史惩罚 $H$ | 0.15 | **0.10** |
| 风险 $R$ | 0.15 | **0.10** |

六项之和为 1。语义项虽然权重最大，但**无法单独决定结果**：
$S=1$ 时贡献 0.30，仍小于"$I$ 0.25 + $N$ 0.10 + $D$ 0.15"的合计 0.50。

> ⚠️ 权重变了，demo 的效用值也随之变化：
> F1 从 0.325 → **0.219**，F2 从 0.255 → **0.169**，排序结论不变（F1 仍胜），分差从 0.070 缩到 0.050。

### 4.3 语义消融（合成场景）

`PYTHONPATH=code python -m exploration.ablate_semantic`

演示（同一张栅格，只改记忆里的物体）：

| 场景 | 结果 |
|---|---|
| ① 记忆里没有物体 | F1(U=0.336) > F2(U=0.193) —— 纯几何，F1 胜 |
| ② F2 旁有椅子（目标=椅子） | **F2(U=0.493) > F1(U=0.451)** —— 语义翻转 |
| ③ F2 旁只有一张床 | F1 > F2 —— 无关物体不改变排序 |
| ④ F2 旁的椅子只是低置信候选(c=0.25) | F1 > F2 —— 弱证据不推翻几何 |
| ⑤ F2 旁有餐桌 | **F2 > F1** —— 通过共现关系间接生效 |

消融（48 个用例，Top-1 准确率）：

| w_S | σ=1 m | σ=2 m | σ=4 m |
|---|---|---|---|
| 0.00 | 50.0% | 50.0% | 50.0% |
| 0.20 | 54.2% | 54.2% | 50.0% |
| 0.30 | 62.5% | 62.5% | 58.3% |
| 0.40 | 70.8% | 79.2% | 75.0% |
| 0.50 | 83.3% | **87.5%** | 83.3% |

结论：**基线 50% 即随机水平**，说明纯几何完全无法区分；$w_S\ge0.3$ 开始生效；
准确率到不了 100% 是设计使然（三分之一的用例是 $c_o=0.25$ 的弱证据，本就不该翻转）。

> ⚠️ 以上全部是**合成场景**，只能证明机制按设计工作，**不是真实场景的性能**。

## 5. 需要队长做什么

### ① 跑 S1 真实评测（主要任务）

脚本：`evals/eval_frontier_choice.py`

它吃的是一个 `manifest.jsonl` + 每个决策点一个 `.npy` 栅格。最小字段：

```json
{"dp_id":"2azQ1b91cZZ-0007","scene":"2azQ1b91cZZ","goal_category":"chair",
 "goal_xy":[3.42,-1.07],"resolution":0.1,"origin":[-2.0,-3.5],
 "robot_cell":[42,31],"map_version":7,"grid":"grids/dp0007.npy","objects":[...]}
```

在现有回合脚本里，每轮决策前加一行就能存下来：

```python
import sys; sys.path.insert(0, "<repo>/evals")     # 或者直接把该文件加进 PYTHONPATH
from eval_frontier_choice import dump_decision_point

dump_decision_point(
    out_dir="/root/autodl-tmp/data/frontier_choice",
    values=occupancy.values,          # 占据栅格 -1/0/100
    robot_cell=robot_cell, resolution=0.1, origin=origin,
    map_version=map_version,
    goal_category=goal_spec.category,
    goal_xy=(goal_instance.x, goal_instance.z),   # ← 来自 .house 标注，仅作真值
    objects=models_from_m2(online_update),        # ← 当时 M2 里的物体（可选）
    scene="2azQ1b91cZZ",
)
```

然后：

```bash
PYTHONPATH=code python evals/eval_frontier_choice.py \
  --manifest /root/autodl-tmp/data/frontier_choice/manifest.jsonl \
  --hard_only --out .../report.json
```

**真值怎么取**：`goal_xy` 用 Matterport3D `.house` 的 objects 段（类别 + 世界坐标），
或 Habitat 的 `SemanticScene`。⚠️ **只能用来判分，绝对不能喂给打分函数**，否则是特权信息泄漏。

**建议规模**：3–5 个场景、每个 30–60 个决策点，跑一次大约几分钟（不需要 GPU）。

### ② 确认 M3 是否要填 `nearby_object_ids`

`FrontierCandidate` 里有这个字段但现在没人写。我们**没有**改 M3，
而是让探索侧通过 `object_query` 回调去查 M2，保持单向依赖。
如果队长更希望在 `update_snapshot()` 里直接把附近物体写进记录，也可以，
只是要注意别让记忆模块依赖探索模块的结构。

### ③ 确认 `rank()` 的接口

`rank(snapshot, records, mapping, goal=None, semantic=None, object_query=None)`。
决策侧（hyf）只需要多传一个 `goal`（`GoalSpec` 或字符串都行），
语义就可以生效；不传则完全退化为原来的几何排序。

## 6. 已知边界（请勿高估）

1. **只覆盖"已经见过目标"的场景**。$\mathcal{O}_F$ 来自记忆，
   目标从未被检出时所有前沿 $S=0$，系统退回纯几何。
   "开局该往哪个房间走"这个问题，本版本**没有回答**。
   要覆盖它需要引入房间级预测（$\sum_r P(r\mid F)P(r\mid g)$），即"路径 B"，尚未实现。
2. **合成场景的数字不是性能**。第 4.3 / 4.4 节全部是人工构造的用例。
3. **测地距离目前用欧氏距离近似**。隔墙的物体会被算成"很近"。
   生产环境应注入基于测地距离的 `object_query`。
4. **知识库覆盖面有限**。54 个类别以外的物体一律返回关联 0（宁可不给先验，也不瞎猜）。

## 7. 回滚方式

任何一处想退回纯几何，只需不传参数：

```python
ranked = explorer.rank(snapshot, records, mapping)
```

或显式传 `semantic=NullProvider()`。渲染层不做任何假设，不需要改调用方代码。
