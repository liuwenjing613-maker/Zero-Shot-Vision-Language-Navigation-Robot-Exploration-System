## 三、接口定义（与代码一致）

### 3.1 `RobotBackend`

文件：`code/execution/robot_backend.py`

```python
class RobotBackend(ABC):

    @abstractmethod
    def observe(self) -> ObservationPacket: ...

    @abstractmethod
    def scan(self) -> List[ObservationPacket]: ...

    @abstractmethod
    def navigate_to(self, pose: Sequence[float]) -> ExecutionResult: ...

    @abstractmethod
    def cancel_navigation(self) -> ExecutionResult: ...

    @abstractmethod
    def stop(self) -> ExecutionResult: ...

    # 有默认实现，子类可选重写
    def close(self) -> None: ...
```

**约定**：
- 所有坐标是世界坐标系 3D 点，单位米
- 失败通过 `status` / `error_code` 表达，**不抛异常**（调用方是状态机，要靠错误码进恢复流程）
- `navigate_to` **阻塞**：走完才返回，第一版不会出现 `RUNNING`

### 3.2 `ExecutionResult`

文件：`code/common/schemas.py`

```python
@dataclass
class ExecutionResult:
    task_id: str
    action_id: str
    status: str                    # RUNNING / SUCCEEDED / FAILED / CANCELED / TIMEOUT
    final_pose: Optional[Sequence[float]] = None
    path_length: float = 0.0
    execution_time: float = 0.0
    error_code: Optional[str] = None
    error_message: Optional[str] = None

    def to_dict(self) -> Dict[str, Any]: ...
    @classmethod
    def succeeded(cls, task_id, action_id, **kw) -> "ExecutionResult": ...
    @classmethod
    def failed(cls, task_id, action_id, error_code, error_message="", **kw) -> "ExecutionResult": ...
```

### 3.3 `TaskExecutor`

文件：`code/execution/task_executor.py`

```python
PoseResolver = Callable[[str, str], Optional[Sequence[float]]]

class TaskExecutor:
    def __init__(self, backend: RobotBackend,
                 pose_resolver: Optional[PoseResolver] = None): ...

    def execute(self, decision: ActionDecision) -> ExecutionResult: ...
```

**支持的动作**：

| `action_type` | 调用 | 说明 |
|---|---|---|
| `EXPLORE_FRONTIER` | `navigate_to(resolver("frontier", frontier_id))` | 去探索点 |
| `APPROACH_TARGET` | `navigate_to(resolver("target", target_id))` | 接近目标 |
| `STOP` | `stop()` | 结束任务 |
| 其他 | `FAILED` + `UNSUPPORTED_ACTION` | 留扩展 |

**错误码**（`code/common/enums.py`）：

| 错误码 | 触发场景 |
|---|---|
| `NO_PATH` | 目标不可达 / A\* 找不到路径 |
| `TIMEOUT` | 超过最大步数 |
| `STUCK` | 路点耗尽但未到达 |
| `UNSUPPORTED_ACTION` | 动作类型未实现 |
| `UNKNOWN_ID` | 缺少 ID / resolver 解析不出坐标 |
| `INTERNAL_ERROR` | 后端抛异常（被 Executor 兜住） |

## 四、数据流

```
ActionDecision {action_type, target_id / frontier_id}
        │
        ▼
    TaskExecutor.execute()
        │
        ├─ pose_resolver(kind, id) → 世界坐标
        │
        ▼
    RobotBackend.navigate_to(pose)
        │
        ├─ snap_point → ShortestPath → find_path
        └─ 逐帧 set_state 推进（≤ max_steps）
        │
        ▼
    ExecutionResult ──► Decision / Memory
```

## 五、设计决策记录

> 这 6 个点在设计阶段列出，现已全部定案并落地。

| # | 问题 | 决策 | 代码位置 |
|---|---|---|---|
| 1 | `navigate_to` 阻塞还是非阻塞 | **阻塞** | `habitat_backend.py` `navigate_to()` |
| 2 | `scan()` 返回什么 | **多帧**，朝向量 `scan_views` 默认 4 | `habitat_backend.py` `__init__` / `scan()` |
| 3 | ID → 坐标怎么解析 | **注入 `pose_resolver`** | `task_executor.py` |
| 4 | 错误码 | **字符串常量** | `common/enums.py` `ErrorCode` |
| 5 | 是否单独做 `safety_guard` | **不做**，步数上限 + 超时写在 `navigate_to` 循环里 | `habitat_backend.py` |
| 6 | 代码放哪 | **`code/` 下平铺**（不设版本目录），`docs/` 放文档 | 本文件第二节 |

### 实现时发现并修正的问题

**`scan(views=4)` 不能把参数放在方法签名上。**

契约测试报：

```
AssertionError: ['self'] != ['self', 'views']   ← scan 参数不一致
```

抽象接口是 `scan(self)`，实现多一个参数就破坏了「换后端不改上层」的保证。
已改为构造参数 `HabitatBackend(scan_views=4)`。

### `HabitatBackend` 的已知限制

1. **移动是瞬移**：`tick` 的实现是「读位姿 → 算新坐标 → `set_state` 写回」，
   没有碰撞检测、没有动力学。真机必须换成底盘运动控制。
2. **未在仿真中验证**：代码复用了之前在 Habitat 上验证过的 A\* / snap 逻辑，
   但新接口（`navigate_to` 阻塞版 + `scan`）尚未跑过真实场景。
3. **`cancel_navigation` 需要另一个线程**：因为 `navigate_to` 是阻塞的，
   同线程无法调用取消。第一版只保留接口，实际取消依赖多线程或后续异步改造。
