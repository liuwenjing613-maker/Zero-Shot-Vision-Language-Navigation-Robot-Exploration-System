## 三、算法流程

```
占据栅格 (-1 未知 / 0 空闲 / 100 占用)
        │
        ├─► ① Frontier Cell 检测
        │      free ∩ dilate₈(unknown)
        │      只保留安全余量足够的格子（可选）
        │
        ├─► ② Region 聚类
        │      8 邻域连通分量，过滤少于 12 格的区域
        │
        ├─► ③ Viewpoint 生成（每个区域）
        │      在质心周围 1.5m 内采样候选：空闲 + 可达 + clearance ≥ 0.3m
        │      对每个候选算：
        │        G = 射线能看到的未知格数（72 条射线，遮挡感知）
        │        D = 从机器人的测地距离（Dijkstra on free cells）
        │        R = 1 − clearance/0.6
        │      评分 J = 0.55·G_n − 0.30·D_n − 0.15·R
        │
        └─► ④ Utility 打分与排序
               U = 0.35·IG + 0.15·N − 0.20·D − 0.15·H − 0.15·R
```

### 比队长给的基线 `detect()` 强在哪

| 方面 | 基线（`exploration_adapter.detect`） | 本实现 |
|---|---|---|
| Viewpoint 选择 | 取「离簇质心最近的可视格」 | **采样多个候选并打分**（信息增益 + 路径 + 风险） |
| 信息增益 | 用簇大小近似 | **射线遮挡扫描**，实际数可见未知格 |
| 路径成本 | 欧氏距离（不检查可达） | **测地距离**（Dijkstra，绕障碍） |
| 风险 | 只做 0.22m 安全过滤 | 按 clearance 连续归一化 |
| 历史 | 不在检测层 | 从 Memory 的 `visit_count`/`failed_count` 接入打分 |

## 四、对外接口

### 4.1 `FrontierExplorer.detect(...) -> snapshot`

产出可直接喂给队长 `FrontierMemory.update_snapshot()` 的快照。

```python
snapshot = explorer.detect(
    values,            # np.ndarray，-1/0/100
    resolution,        # 0.1
    origin=(x0, z0),
    robot_cell=(row, col),
    map_version=7,
    complete=True,
    floor_y=0.0,       # 世界 Y，用于补全 3D 坐标
)
```

返回：

```python
{
  "snapshot_id": "7",
  "map_version": 7,
  "complete": True,
  "candidates": [
    {
      # FrontierMemory 认识的四个字段
      "local_candidate_id": "1",
      "centroid_xy": (x, z),
      "safe_viewpoint_xy": (x, z),
      "cluster_cells": [[r, c], ...],
      # 打分用的扩展字段（update_snapshot 会忽略）
      "cluster_size": 77,
      "gain_cells": 1301,
      "path_length": 1.61,
      "clearance": 0.60,
      "reachable": True,
      "floor_y": 0.0,
    }
  ]
}
```

> ✅ 扩展字段安全：队长的 `update_snapshot()` 只读那四个键，多余的会被忽略。

### 4.2 `FrontierExplorer.rank(snapshot, records, mapping) -> list[FrontierCandidate]`

```python
mapping = frontier_memory.update_snapshot(snapshot)   # {"1": "F0001", ...}
ranked = explorer.rank(snapshot, frontier_memory.records, mapping)
```

- `records` / `mapping` 可以省略（单元测试场景），此时用本地 ID
- 返回的 `FrontierCandidate` 按 `local_utility` 降序

### 4.3 `FrontierExplorer.explore(...)`

`detect + rank` 的组合，不需要记忆模块时用。

## 八、实现中的两个坑（记录备查）

### 坑 1：安全过滤会删光 Frontier Cell

最初用 `clearance >= 0.22m` 过滤 Frontier Cell，结果一个都检测不到。

**原因**：Frontier Cell 按定义紧邻未知区域，`clearance_map` 只有约 1 格（0.1m），必然小于阈值。

**修正**：安全距离只用于筛选 **Viewpoint**（`viewpoint.py` 的 `min_view_clearance`），不用于筛选 Frontier Cell。

### 坑 2：min-max 归一化放大微小差异

1301 vs 1219 个可见未知格，min-max 后变成 1.0 vs 0.0，Utility 差距 0.5，严重失真。

**修正**：改用**比值归一化**（除以最大值）→ 1.0 vs 0.937，Utility 0.325 vs 0.255。

1. **未在 Habitat 运行时验证** —— 已经用队长的 `OccupancyMemory` / `FrontierMemory` 做过集成验证（见 6.1），但还没有用**真实传感器累积出来的地图**跑过。需要服务器。

2. **没有多个 Viewpoint** —— 第一版每个区域只保留一个（队长文档允许复杂区域保留多个）。
3. **语义收益 S 未实现** —— 公式里留了 `semantic_utility` 字段，第一版为 None（等 Qwen 重排序）。
4. **权重是初值** —— 0.35/0.15/0.20/0.15/0.15 是保守估计，需要 Habitat 实验调（队长文档 4.4 节）。
5. **性能未压测** —— 射线扫描是候选数 × 射线条数 × 步长，大地图上需要降低射线条数或采样数。
6. **`nearby_object_ids` / `associated_place_id` / `visual_cues` 未填** —— 需要接 Object Memory 和 Topology，第一版留空。
